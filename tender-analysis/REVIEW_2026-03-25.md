## 经验总结

### 1. Agent调度机制

**问题：** CEO Board Monitor cron job 每15分钟巡检，但只监控不派发任务，导致所有任务卡在 PENDING 状态。

**解决：** 扩展 cron job 逻辑，增加第四步"处理 PENDING 任务（派发 agent）"，真正执行 spawn 操作。

**教训：** 监控不等于执行，需要明确区分"巡检"和"干活"两个角色。

### 2. clawteam vs OpenClaw sessions_spawn

**问题：** clawteam spawn 依赖 Claude Code CLI，但该 CLI 需要 OAuth 浏览器认证，不支持纯后台运行。subprocess 模式同样立即退出。

**解决：** 使用 OpenClaw 原生 `sessions_spawn` 派发 subagent，不依赖外部 CLI，稳定性更高。

**教训：** 集成外部工具时需验证其 headless 模式支持情况。

### 3. 多Agent协作流程

```
需求提取 → 物流方案 → 成本模型 → 投标标书 → QA审核
                                                    ↓
                        ← QA反馈 ← ← ← ← ← ← ← ← ←
                         问题修正
```

**成功要素：**
- 清晰的链路设计（每步有明确输入输出）
- QA反馈循环（发现问题后返回对应Agent修正）
- 任务状态跟踪（clawteam board 可视化）

### 4. 投标文件质量控制

QA发现5个高严重程度问题，全部在修正流程中解决：
- H1 运输费+卸车费缺失
- H2 客户端收费项未填
- H3 NCDC面积错误
- H4 SJDC自动化仓定价偏低
- H5 CNY临时仓选址方案缺失

**教训：** QA审核是质量门禁，不可跳过。
